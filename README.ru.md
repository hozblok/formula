## Документация

**formula** содержит чувствительный к регистру (по умолчанию) парсер строк.
Представим, что у нас есть строковое выражение: `"(x^2+y)/sin(a*pi)"`:

```python
>>> from formula import Solver
>>> formula = Solver("(x^2+y)/sin(a*pi)", precision=32)
```

Затем мы хотим вычислить значение этой функции в следующей точке:

```python
>>> point = {"x": "3", "y": "3e-20", "a": "-0.5"}
```

И достаточно вызвать объект `formula`, чтобы вычислить значение выражения или производную выражения в этой точке:

```python
>>> formula(point) # (3^2 + 3e-20)/sin(-pi/2)
'-9.00000000000000000003'
>>> formula(point, derivative="x") # 2*3/sin(-pi/2)
'-6'
>>> formula(point, derivative=("y", "a")) # [1/sin(-pi/2),- (3^2 + 3e-20) * cos(-pi/2) / sin(-pi/2)]
['-1', '-1.5633175729821453046351823925394e-47']  # cos(-pi/2) — это эпсилон, а не точный 0
```

### Использование `Number` как Python-значения произвольной точности

`Number` — это небольшая питоничная обёртка вокруг `Solver`, позволяющая составлять
выражения со стандартными арифметическими операторами и операторами сравнения, при этом
сохраняя произвольную точность на всём протяжении:

```python
>>> from formula import Number
>>> a = Number("1.0000000000000000000000000001", precision=64)
>>> b = Number("2", precision=64)
>>> str(a + b)
'3.0000000000000000000000000001'
>>> str(a * b)
'2.0000000000000000000000000002'
>>> str(abs(Number("-3.14", precision=32)))
'3.14'
>>> a > b
False
>>> a == Number("1.0000000000000000000000000001", precision=64)
True
```

Равенство сравнивает строки `(real, imag)` из `pair` — точные комплексные тождества сравниваются как равные, но
выражения с дрейфом — нет:

```python
>>> Number("i*i") == Number("-1")   # точно — без дрейфа
True
>>> Number("i^4") == Number("1")    # дрейф в комплексном ^ → False
False
```

`Solver.pair(values, format_digits, format_flags)` возвращает
кортеж `(real_str, imag_str)`, отформатированный согласованно — результаты только с вещественной частью
получают `(value, "0")`, так что пары сравнимы побайтово. Используется внутренне
в `Number.__eq__` и `Number.__hash__`.

Поддерживаемые операторы: `+`, `-`, `*`, `/`, `**` (также записывается как `^` внутри
выражений), `abs()`, `==`, `<`, `<=`, `>`, `>=`.

### Поиск всех пересечений луча с поверхностью

`RaySurface` находит **каждое** пересечение луча `r(t) = O + t·d` с
неявной поверхностью `F(x, y, z) = 0`. Подстановка луча сводит поверхность к
функции одной переменной `g(t) = F(O + t·d)`, так что пересечения — это в точности вещественные
корни `g` на `[t_min, t_max]`. `t` измеряется в единицах `|d|` (направление
нормализуется внутренне), так что для единичного `d` это расстояние вдоль
луча.

```python
>>> from formula import RaySurface
>>> rs = RaySurface("x*x + y*y - 1", precision=24)      # единичный цилиндр
>>> ts = rs.intersect((-2, 0, 0), (1, 0, 0), t_max=10)  # два пересечения: t≈1, t≈3
>>> len(ts)
2
>>> pts = rs.points((-2, 0, 0), (1, 0, 0), t_max=10)    # (x, y, z) на поверхности
>>> len(pts)
2
```

Выберите метод поиска корней с помощью `method=`:

| `method`      | Лучше всего для                            | Гарантия |
|---------------|--------------------------------------------|-----------|
| `auto`        | по умолчанию — выбирает по поверхности      | Sturm для многочленов, иначе Chebyshev ∪ subdivision |
| `sturm`       | алгебраические поверхности (квадрики, торы, …)     | точный, полный подсчёт вещественных корней |
| `chebyshev`   | гладкие, малоосциллирующие аналитические (`sin`/`exp`/…) | самопроверяющаяся *аппроксимация*; ловит касания |
| `subdivision` | общие/осциллирующие поверхности               | исключение по оценке производной (практически надёжно) |
| `sampling`    | быстрые, хорошо разделённые корни                | нет — может пропустить тонкие/касательные особенности |

`auto` направляет алгебраические поверхности на `sturm` (точный), а другие вещественные поверхности на
`chebyshev`, согласованный с `subdivision` в качестве страховки. Корни чётной кратности
(касательные), которые обычная выборка перешагивает, восстанавливаются:

```python
>>> rs = RaySurface("x*x + y*y + z*z - 1", precision=24)   # сфера
>>> len(rs.intersect((-2, 1, 0), (1, 0, 0), t_max=10, method="sturm"))  # по касательной
1
```

Опции-ключевые слова: `t_min` (по умолчанию `0`), плюс настройки конкретных методов, такие как
`max_degree` (sturm), `cheb_degree` (chebyshev) и `m2_samples` (subdivision).
Комплекснозначные поверхности поддерживаются методом `sturm` (вещественные пересечения — это
общие корни `Re g` и `Im g`); остальные бэкенды работают только с вещественными.

См. [doc/ray-surface-intersections.ru.md](doc/ray-surface-intersections.ru.md) для
полного руководства и ограничений, и [doc/ray-surface-design.ru.md](doc/ray-surface-design.ru.md)
для заметок по дизайну. Оговорки кратко:

- `subdivision` *практически* надёжен, а не формально строг: его тест на
  исключение настолько хорош, насколько хороша оценённая граница на `g''`.
- `chebyshev` самопроверяет *аппроксимацию*, а не изоляцию корней. Его
  шаг Chebyshev→моном плохо обусловлен при высокой степени, поэтому он может молча
  пропустить корни на плотно осциллирующих поверхностях; там предпочитайте `subdivision`/`auto`.
- `sturm` точен только до умеренной алгебраической степени (по умолчанию предел 16; повышайте
  `max_degree` с осторожностью — равномерно распределённая интерполяция деградирует при высокой степени).

## Численная точность и дрейф

`precision=N` гарантирует N десятичных цифр в **представлении**
значения, но не то, что каждая операция попадёт в математически точный результат.
Некоторые выражения накапливают ошибку с плавающей точкой в последних цифрах, даже
несмотря на то, что математическое тождество точно.

### Операции, точные при заданной точности

- `+`, `-`, `*`, `/` над вещественными числами.
- `+`, `-`, `*`, `/` над комплексными числами (включая длинные цепочки `*` —
  `i*i*i*i*i*i*i*i` вычисляется ровно в `1`).
- `^` с **вещественным** основанием и целым показателем (использует возведение в квадрат с умножением
  внутренне): `2^10`, `1.1^7` и т.д.
- `abs(z)`, когда `re² + im²` — полный квадрат (`abs(3+4*i) == 5`,
  `abs(i) == 1`).
- Трансцендентные функции в точках с точными алгебраическими результатами: `sin(0)`,
  `cos(0)`, `exp(0)`, `log(1)` и т.д.
- Тождество Пифагора в вещественном пространстве: `sin(pi/4)^2 + cos(pi/4)^2 == 1`.

### Операции, которые дрейфуют (заметно в последней цифре или дальше)

- **`^` с комплексным основанием, даже для тривиальных целых показателей.**
  Комплексный `pow(a, b)` вычисляется как `exp(b·log(a))`, трансцендентная
  цепочка — для комплексных значений в boost.multiprecision нет специализации
  для целых показателей. Дрейф растёт с величиной
  показателя и результата:

  | Выражение          | Математическое значение | Вычислено при `precision=24`                                          |
  |---------------------|--------------------|---------------------------------------------------------------------|
  | `i^4`               | `1`                | `1 + i·1e-24`                                                       |
  | `i^64`              | `1`                | `1 + i·1.2e-23`                                                     |
  | `(1+i)^16`          | `256`              | `256 + i·3.78e-21`                                                  |
  | `(1+i)^64`          | `4294967296`       | `4294967296 + i·2.5e-13` (≈ половина доступных цифр потеряна)      |
  | `exp(2*i*pi)`       | `1`                | `1 + i·1e-24`                                                       |

  **Обходной путь:** если показатель — небольшое целое, замените `z^n`
  явным произведением `z*z*…*z` — умножение точно для
  комплексных значений.

- **Трансцендентные функции** (`sin`, `cos`, `exp`, `log`, `asin`,
  `acos`, `atan`, `tan`), когда математический результат иррационален.
  `log(exp(1))` округляется до чистой `1` при заданной точности; полный
  кусок памяти (`format_digits=0`) вскрывает дрейф цикла:
  `1.0000000000000000000000018…`. То же выражение с `+i*0` идёт по
  комплексному пути и дрейфует в другую сторону: `0.99999999999999999999999959…`.

## Разработка

### Сборка из исходников

Рабочий C++ тулчейн требуется, когда ни один wheel не подходит для вашей платформы
или когда вы выгружаете проект для разработки:

| ОС       | Тулчейн                                                       |
|----------|-----------------------------------------------------------------|
| Linux    | `g++` (или `clang++`); `python3-dev`                             |
| macOS    | Xcode Command Line Tools (`xcode-select --install`)             |
| Windows  | Visual Studio Build Tools (рабочая нагрузка C++)                        |

```bash
git clone https://github.com/hozblok/formula.git
cd formula
python -m venv .venv && source .venv/bin/activate
python -m pip install -e .[test]
```

Editable-установка собирает C++-расширение и помещает получившийся
`_formula.so` (или `.pyd`) прямо в дерево исходников, так что `pytest` из
корня репозитория корректно разрешает `formula._formula`.
