# Пересечения луча с поверхностью (`RaySurface`)

`RaySurface` находит **каждое** пересечение луча с неявной поверхностью
`F(x, y, z) = 0` с произвольной точностью.

Этот документ объясняет механизм, проходит по каждому бэкенду поиска корней, формулирует **границы применимости**. О том, *почему* приняты те или иные проектные решения, и о
журнале ревью см. [ray-surface-design.ru.md](ray-surface-design.ru.md).

## Быстрый старт
```python
rs = RaySurface("x*x + y*y - 1", precision=24)
ts = rs.intersect(origin=(-2,0,0), direction=(1,0,0), t_max=10)
# -> [Number('1...'), Number('3...')]  — параметры t вдоль луча
pts = rs.points((-2,0,0), (1,0,0), t_max=10)
# -> [(x,y,z), ...] — те же пересечения в координатах
```

## Публичный API

```python
rs = RaySurface(expression, precision=24)

rs.intersect(origin, direction, t_max, method="auto", t_min=0, **options)
    # -> отсортированный list[Number] параметров луча t, где луч встречает F = 0

rs.points(origin, direction, t_max, **kwargs)
    # -> list[(x, y, z)] точек пересечения на поверхности, отсортированных по t
```

- `origin` / `direction` — это тройки `(x, y, z)`; `direction` должен быть ненулевым.
- Корни возвращаются как `Number` произвольной точности, по возрастанию.
- `points()` восстанавливает **полную** 3-D точку даже для осей, которые
  поверхность игнорирует (цилиндр не зависит от `z`, но `z` луча всё равно
  сообщается):

```python
>>> rs = RaySurface("x*x - 1", precision=24)   # зависит только от x
>>> rs.points((-2, 5, 7), (1, 0, 0), t_max=10, method="sturm")
[(Number('-0.999...'), Number('5'), Number('7')),
 (Number('0.999...'),  Number('5'), Number('7'))]
```

**`method`** — бэкенд поиска корней:

- `"auto"` (по умолчанию)
- `"sturm"`, `"chebyshev"`, `"subdivision"`, `"sampling"`

Опции по методам:

- **`sturm`:** `max_degree`
- **`chebyshev`:** `cheb_degree`
- **`subdivision`:** `m2_samples`, `region_tol`
- **`sampling`:** `samples`

## Параметры
| Аргумент | Смысл |
|---|---|
| origin | начало луча (x,y,z) |
| direction | направление; ненулевое; длина не важна |
| t_max | правый конец интервала поиска |
| t_min | левый конец (по умолчанию 0) |
| method | см. ниже; по умолчанию "auto" |


## method — что выбрать

| method | Когда | Опции (редко нужны) |
|---|---|---|
| `auto` | не уверены; по умолчанию | — |
| `sturm` | полином, квадрика, комплекснозначная | `max_degree` (16) |
| `chebyshev` | гладкая аналитика (`sin`, `exp`, …), мало корней | `cheb_degree` (32) |
| `subdivision` | осциллирующая, гофрированная, неизвестная | `m2_samples` (200), `region_tol` (1e-6·Δt) |
| `sampling` | быстрая проверка; **не** строгий | `samples` (256) |

Подробнее — [Бэкенды](#бэкенды), [Выбор метода](#выбор-метода).

## Сведение (как это работает внутри)

Луч — это `r(t) = O + t·d`. Подстановка его в уравнение поверхности схлопывает
трёхпеременную поверхность в функцию одной переменной

```
g(t) = F(O + t·d)
```

и пересечение — это в точности **вещественный корень `g` на `[t_min, t_max]`**.
Так что «найти все пересечения» превращается в «найти все вещественные корни
`g`», и вся задача делегируется подключаемым одномерным искателям корней в
[`src/formula/_roots/`](../src/formula/_roots/).

Перед трассировкой `direction` `d` приводится к единичной длине. Поэтому `t` — это реальное
расстояние вдоль луча (**длина дуги**) в тех же единицах, что и координаты, а сама
длина `d` на результат не влияет — важно только направление. Отсюда `(1, 0, 0)` и
`(7, 0, 0)` дают одни и те же `t`.



```python
>>> from formula import RaySurface
>>> rs = RaySurface("x*x + y*y - 1", precision=24)       # единичный цилиндр
>>> rs.intersect((-2, 0, 0), (1, 0, 0), t_max=10)        # вход в x=-1 (t=1), выход в x=1 (t=3)
[Number('1.00000000000000000000002', precision=24), Number('2.99999999999999999999999', precision=24)]
>>> rs.intersect((-2, 0, 0), (7, 0, 0), t_max=10)        # длиннее d, но то же направление -> те же t
[Number('1.00000000000000000000002', precision=24), Number('2.99999999999999999999999', precision=24)]
```


## Как строятся `g(t)` и `g'(t)`

Никакой символьной подстановки не выполняется. `RaySurfaceFunction` повторно
использует существующий вычислитель:

- `g(t) = F(O + t·d)` через `Solver.evaluate` в точке `O + t·d`.
- `g'(t) = ∇F · d` через `Solver.get_derivative` по каждой оси (цепное правило),
  свёрнутое с нормированным направлением. Вклад дают только оси, от которых
  поверхность действительно зависит (у остальных `∂F/∂a = 0`).

Оба вычисляются с полной точностью, что и нужно решателю всех корней, чтобы
разделить близкие корни и заверить их количество.


## Бэкенды

Каждый бэкенд реализует один контракт,
`find_all(func, t_min, t_max, precision, **opts) -> list[Number]`, и может быть
выбран напрямую или достигнут через `auto`.

### `sturm` — точный, для алгебраических поверхностей

Полиномиальный путь. Он **полон** (доказуемое количество вещественных корней)
для алгебраического `g`:

1. Сэмплировать `g` в `max_degree + 2` узлах и восстановить его мономиальные
   коэффициенты разделёнными разностями Ньютона (дополнительный узел позволяет
   обнаружить и отвергнуть поверхность сверх степени, а не молча недо-подогнать её).
2. Сделать его **свободным от квадратов** (`p / gcd(p, p')`), чтобы каждый корень
   был простым.
3. Построить **цепь Штурма** и считать корни на любом подынтервале по разности
   числа смен знака на его концах.
4. **Изолировать** каждый корень в своей скобке и **бисекцией** довести до точности.

Комплекснозначные поверхности поддерживаются: вещественные пересечения — это
общие корни `Re g` и `Im g`, то есть корни их полиномиального gcd.

### `chebyshev` — для гладких аналитических поверхностей (`sin`, `exp`, `log`, …)

`g` аппроксимируется на `[t_min, t_max]` интерполянтом Чебышёва в узлах
Чебышёва–Гаусса. Степень наращивается, пока не сойдётся спектральный хвост
(самозаверяющая *подгонка*). Интерполянт переводится в мономиальный прокси, чьи
корни изолируются той же машинерией Штурма, а затем шлифуются на **истинной** `g`
Ньютоном. Он улавливает корни чётной кратности (касательные), которые сэмплинг
перешагивает. См. [его границу](#границы-chebyshev) — мономиальное преобразование
ограничивает область, где этому бэкенду можно доверять.

### `subdivision` — общие / осциллирующие поверхности

Чисто питоновская золотая середина. На каждом подынтервале оценка Тейлора
исключает области, которые доказуемо не могут содержать корень:

```
|g(t) − g(m)| ≤ |g'(m)|·h + (M2/2)·h²       (m = середина, h = полуширина)
```

так что корень требует `|g(m)| ≤ |g'(m)|·h + (M2/2)·h²`. `M2` — это оценка
`max|g''|`, сэмплированная из `g'` и раздутая. Уцелевшие интервалы доводятся до
простых корней (Ньютон в скобке) или касаний (`g'=0` при `g≈0`); точки поворота,
где `g≠0`, отвергаются. Практически надёжно, но **не** формальное доказательство —
ровно настолько хорошо, насколько хороша оценка `M2`.

### `sampling` — эталонный оракул

Смены знака на сетке, уточнённые предохранённым Ньютоном. Не строг: корни чётной
кратности и подсеточные особенности пропускаются по построению. Существует как
базовая линия, с которой сверяются строгие бэкенды. Неконечные сэмплы (вблизи
особенности) пропускаются, а не сообщаются как фантомные корни.

### `auto` — диспетчеризация по умолчанию

- **Алгебраические** поверхности → `sturm` (точно). Если Штурм бросает исключение
  (например, степень выше предела), `auto` **откатывается** к общим бэкендам
  вместо отказа.
- **Прочие вещественные** поверхности → дедуплицированное **объединение
  `chebyshev` и `subdivision`**, чтобы слепое пятно ни одного из методов не
  потеряло корень. Любой из них может отказать численно и выпасть; комплексная
  поверхность всё равно бросает информативное исключение.

## Разобранные примеры

```python
from formula import RaySurface, Number

# 1) Сфера, два пересечения
rs = RaySurface("x*x + y*y + z*z - 1", precision=48)
rs.intersect((-2, 0, 0), (1, 0, 0), t_max=10)            # -> [1, 3]

# 2) Касательный (скользящий) луч: корень чётной кратности
rs.intersect((-2, 1, 0), (1, 0, 0), t_max=10, method="sturm")   # -> [2]
rs.intersect((-2, 1, 0), (1, 0, 0), t_max=10, method="sampling")# -> []  (пропущен)

# 3) Квартика (x^2-1)(x^2-4): четыре корня вдоль луча
RaySurface("(x*x - 1) * (x*x - 4)", 48).intersect(
    (-3, 0, 0), (1, 0, 0), t_max=6, method="sturm")      # -> [1, 2, 4, 5]

# 4) Гофрированная стенка капилляра, радиус 1 + 0.3 sin(4z): 12 корней при z = k·pi/4
RaySurface("x*x + y*y - (1 + 0.3*sin(4*z))^2", 32).intersect(
    (1, 0, 0), (0, 0, 1), t_max=10, t_min="0.1", method="auto") # -> 12 корней

# 5) Тор (изогнутый капилляр): квартика степени 4, до четырёх пересечений на луч.
#    (x^2+y^2+z^2 + R^2 - r^2)^2 - 4 R^2 (x^2+y^2) = 0, здесь R=2, r=1.
torus = RaySurface("(x*x+y*y+z*z+3)^2 - 16*(x*x+y*y)", 48)
torus.intersect((-4, 0, 0), (1, 0, 0), t_max=10)         # -> [1, 3, 5, 7]
torus.intersect((3, -3, 0), (0, 1, 0), t_max=10, method="sturm")  # скользящий -> [3]
# Изогнутый капилляр — это тор; «часть тора» — это угловой срез [t_min, t_max].

# 6) Комплекснозначная поверхность; вещественные пересечения — общие корни Re g и Im g
RaySurface("(x*x - 1) * (1 + i)", 48).intersect(
    (-2, 0, 0), (1, 0, 0), t_max=10, method="sturm")     # -> [1, 3]

# 7) Начало луча лежит на поверхности: t = 0 — настоящий корень
RaySurface("x*x + y*y - 1", 48).intersect(
    (-1, 0, 0), (1, 0, 0), t_max=10, t_min=0)            # -> [0, 2]
```


## Оценка стратегии

**Верна ли выбранная стратегия?** В основном да, с одним бэкендом (`chebyshev`),
который является слабым звеном.

- **Сведение к `g(t)` с повторным использованием `Solver.evaluate` /
  `get_derivative`** — корректно и экономно. Оно бесплатно наследует произвольную
  точность и не добавляет символьной машинерии. Цена — одно вычисление поверхности
  на каждый сэмпл `g`.

- **Штурм вместо собственных значений сопровождающей / коллегиальной матрицы**
  для алгебраического пути — здесь правильный выбор. В этом проекте нет
  решателя собственных значений произвольной точности; Штурм остаётся внутри мира
  точности `formula` и даёт *доказуемое* количество корней, а не приближённые
  собственные значения. Цена — шаг интерполяции (восстановление полинома), который
  хорошо обусловлен лишь до умеренной степени.

- **`subdivision` как опора надёжности** вместо строгого C++-интервального типа —
  прагматичный выбор. Он целится в реальное слабое место (полнота на
  трансцендентных/осциллирующих поверхностях) без риска для ядрового вычислителя
  и без пересборки. Он меняет формальную строгость на практическую границу `M2`.

- **`chebyshev` с переводом в мономиальный прокси** — спорное решение.
  Чебышёвская *подгонка* превосходна, но перевод её в мономиальный базис и запуск
  Штурма там выбрасывает ровно то преимущество в обусловленности, ради которого
  Чебышёв и существует. При высокой степени мономиальные коэффициенты переполняют
  рабочую точность, и корни молча теряются (см. ниже). Решение собственных значений
  коллегиальной матрицы или рекурсивное чебышёвское подразбиение было бы
  принципиальным исправлением; до тех пор `subdivision` (а значит и `auto`) —
  надёжный путь для плотной осцилляции, а `chebyshev` лучше приберечь для
  низкой-умеренной осцилляции.

- **Диспетчеризация `auto` с объединением + откатом** — обоснована.
  Маршрутизация алгебраических поверхностей к точному бэкенду и объединение двух
  общих бэкендов в остальных случаях — правильное умолчание, а откат Штурм→общий
  убирает режим жёсткого отказа.


## Границы применимости

Сначала геометрический контракт, затем условия и режимы отказа по каждому бэкенду.

**Геометрия / API**

| Требование | За его пределами |
|---|---|
| Переменные поверхности ⊆ `{x, y, z}` | `ValueError` |
| `direction` ненулевой | `ValueError` (раньше был молчаливый `nan`) |
| `t_min ≤ t_max` | `ValueError` |
| Корни сообщаются только в `[t_min, t_max]` | корни вне него не возвращаются |
| `t` — длина дуги в единицах `|d|` | — |

### Границы `sturm`

- **Степень.** Надёжен для алгебраического `g` вплоть до предела по умолчанию
  (степень ≤ 16 при `max_degree=16`); степень **17+** бросает понятную ошибку, и
  `auto` тогда откатывается. Повышение `max_degree` расширяет диапазон, но
  интерполяция разделёнными разностями по равноотстоящим узлам сама по себе плохо
  обусловлена: значительно выше ~степени 20–30 восстановленные коэффициенты (и даже
  *обнаружение* степени) теряют смысл **молча**, так что поверхность сильно сверх
  предела может вернуть неверное количество, а не ошибку. *Смягчение:* держите
  алгебраические степени луча умеренными или разбейте интервал.
- **Свобода от квадратов / gcd на основе допуска.** `deg()` и gcd используют
  численный допуск, поэтому поверхности с крошечным старшим коэффициентом
  относительно остальных, или с двумя корнями куда ближе этого допуска, могут
  получить неверную степень или слиться.
- **Комплексные поверхности.** Вещественные пересечения — это gcd `Re g` и
  `Im g`; общий множитель обнаруживается с точностью до допуска, поэтому
  почти-общие (но не точно общие) множители хрупки.

### Границы `chebyshev`

- **Обусловленность мономиального преобразования (жёсткая граница).**
  Самозаверение гарантирует *подгонку*, а не *изоляцию корней*. Перевод
  высокостепенного чебышёвского интерполянта в мономиальный базис раздувает
  динамический диапазон коэффициентов за пределы рабочей точности, и Штурм на этих
  численно-бессмысленных коэффициентах **молча теряет корни**. Конкретно: плотная
  осцилляция вроде `sin(60·x)` на `[0.1, 5]` возвращает гораздо меньше корней, чем
  истинные 94, при `method="chebyshev"`. *Смягчение:* используйте `subdivision`
  или `auto` для плотной осцилляции, либо повысьте `precision`, чтобы отодвинуть
  поломку на более высокую степень.
- **Аналитичность.** Предполагается, что `g` гладкая на всём интервале.
  Полюс/особенность в диапазоне (например, рациональная поверхность `1/(x−a)`)
  ломает подгонку: степень растёт до предела, прогон медленный, а результат
  ненадёжен.
- **Концы.** Узлы Чебышёва–Гаусса строго внутренние, поэтому корень точно на
  `t_min`/`t_max` восстанавливается бэкенд-независимой сетью концов, а не самой
  подгонкой.
- Только вещественные поверхности (`NotImplementedError` на комплексных).

### Границы `subdivision`

- **Нестрогая `M2`.** `max|g''|` оценивается из `g'` на сетке и раздувается ×2.
  Для осцилляции тоньше сетки оценка **занижается из-за алиасинга**, тест
  исключения ошибочно отбрасывает интервал, содержащий корень, и корни
  **теряются** (повышайте `m2_samples` для высокочастотных поверхностей). Это
  «практически надёжно», но никогда не доказательство.
- **Резкие/узкие особенности.** Бугор уже разрешения кандидатов (например,
  высокий тонкий гауссиан) может быть исключён целиком.
- **Кластеризованные корни.** Корни ближе `region_tol` (по умолчанию
  `span·1e-6`) сливаются.
- **Кратность.** Разрешаются только простые (смена знака) и чётно-касательные
  (`g'=0`, `g≈0`) корни; шаблоны кратности ≥ 3 могут быть пропущены или
  обработаны неверно.
- Только вещественные поверхности.

### Границы `sampling`

- Нестрогий оракул. **Корни чётной кратности невидимы** (нет смены знака), а
  любая особенность между сэмплами пропускается; расширяйте `samples`, чтобы
  уменьшить — но никогда не устранить — этот зазор.
- Только вещественные поверхности; неконечные сэмплы пропускаются.

### Границы `auto`

- **Маршрутизация синтаксическая.** `is_polynomial` отвергает трансцендентные
  функции, ненатуральные степени (`x^-2`, `x^0.5`) и переменные знаменатели, но
  экзотические записи (дробная степень, записанная как вложенная дробь,
  переменный показатель в скобках) могут смаршрутизироваться неверно. Передавайте
  `method=` явно, если сомневаетесь.
- Откат Штурм→общий **покрывает *исключение* Штурма, а не *молчаливую неверную
  подгонку* Штурма** (степень сильно выше предела, см. выше).
- **Допуск объединения.** Два по-настоящему различных корня ближе
  `1e-(precision/2)` сливаются в один.

### Сквозное: шлифовка на основе Ньютона

`sampling`, `subdivision` и `chebyshev` шлифуют корни Ньютоном, которому нужна
`g'`. Поверхность, чья **символьная производная сингулярна в корне**, это ломает —
например, `(x−1)^5`, чья производная формируется как `u^5·5·u'/u` и равна `nan`
при `u=0`. Используйте `sturm`, который убирает кратность через свободу от
квадратов и никогда не вычисляет производную поверхности.


## Разобранные примеры границ

Каждый пример — это минимальный **отказ** (вызов по умолчанию, возвращающий
неверный/неполный результат), за которым следует **обходной путь**. Выводы — это
наблюдаемые значения.

### 1. Предел степени Штурма (`degree > max_degree` бросает)

Надёжно, когда истинная степень `g` равна `≤ max_degree` (по умолчанию 16).

```python
rs = RaySurface("x^17 - x", precision=40)            # g(t) = t^17 - t, степень 17
rs.intersect((0, 0, 0), (1, 0, 0), t_max=2, method="sturm")
# -> ValueError: polynomial degree exceeds max_degree; not a low-degree polynomial
rs.intersect((0, 0, 0), (1, 0, 0), t_max=2, method="sturm", max_degree=17)
# -> [0, 1]                                           (обходной путь: поднять предел)
```

Оговорка — степень на *два и более* выше предела может **молча неверно
подогнаться**, если её высокопорядковое содержимое алиасит через `max_degree+2`
узлов сэмплирования; надёжно *обнаруживается* только `cap+1` (единственный
сторожевой узел). Под `auto` случай `ValueError` автоматически откатывается к
общим бэкендам.

### 2. Обусловленность Штурма при высокой степени (молчаливый недосчёт)

Надёжно, когда восстановленный полином низкостепенный *относительно точности*.
Интерполяция по равноотстоящим узлам плохо обусловлена (Рунге), поэтому высокая
степень при умеренной точности теряет корни без ошибки.

```python
expr = "*".join(f"(x-{k})" for k in range(1, 19))    # 18 различных корней t=1..18
rs = RaySurface(expr, precision=24)
len(rs.intersect((0,0,0),(1,0,0), t_max=19, method="sturm", max_degree=20))
# -> 15            (неверно: три корня потеряны, остальные сдвинулись до ~0.4)
```

Обходной путь: повысить точность (`precision=40` восстанавливает все 18) или
разбить интервал, чтобы каждый кусок был низкостепенным.

### 3. Обусловленность мономиального преобразования Чебышёва (молчаливый недосчёт)

Надёжно только для немногих осцилляций на интервале. Шаг Чебышёв→моном плохо
обусловлен, поэтому плотная осцилляция молча теряет корни.

```python
rs = RaySurface("sin(7*x)")                           # 23 корня на [0,10]
len(rs.intersect((0,0,0),(1,0,0), 10.0, method="chebyshev"))     # -> 10  (13 потеряно)
len(rs.intersect((0,0,0),(1,0,0), 10.0, method="subdivision"))   # -> 23  (обходной путь)
len(rs.intersect((0,0,0),(1,0,0), 10.0, method="auto"))          # -> 23
```

(`sin(k·x)` на `[0,10]` точен при `k ≤ 6`; `k = 7` — первый, кто недосчитывает.)

### 4. Чебышёв вблизи/внутри полюса

Надёжно только когда `g` аналитична на интервале *и* ближайшая особенность хорошо
отделена от него.

```python
rs = RaySurface("1/(x-5) - 1/2", precision=30)        # полюс в x=5, корень в x=7
rs.intersect((0,0,0),(1,0,0), t_max=10, t_min=Number("5.5",30), method="chebyshev")
# -> []            (молчаливый промах: полюс в 5 чуть левее t_min=5.5)
rs.intersect((0,0,0),(1,0,0), t_max=10, t_min=Number("5.5",30), method="subdivision")
# -> [7]           (обходной путь: скобочные бэкенды терпят близкий полюс)
```

Полюс *строго внутри* интервала хуже — подгонка никогда не сходится, растёт до
предела степени, и прогон медленный/ненадёжный.

### 5. Резонанс сетки `M2` подразбиения (молчаливый промах)

Надёжно, когда `m2_samples` разрешает кривизну `g`. Опасность не в сырой частоте,
а в **резонансе** между осцилляцией и сеткой сэмплирования.

```python
rs = RaySurface("sin(126*x)", precision=24)           # 402 корня на [0,10]
len(rs.intersect((0,0,0),(1,0,0), t_max=10, method="subdivision"))
# -> 137           (k·step = 126·(10/200) ≈ 2π: сэмплы g' алиасят, M2 занижена)
len(rs.intersect((0,0,0),(1,0,0), t_max=10, method="subdivision", m2_samples=2000))
# -> 402           (обходной путь: более тонкая сетка M2)
```

### 6. Узкая особенность подразбиения (молчаливый промах)

Надёжно, когда самая узкая особенность разрешается сеткой `m2_samples`.

```python
# высокий гауссов бугор: два корня 1.4934.. и 1.5066.. (≈0.013 врозь)
rs = RaySurface("exp(-16000*(x-1.5)*(x-1.5)) - 0.5", precision=30)
rs.intersect((0,0,0),(1,0,0), 3.0, method="subdivision")              # -> []   (оба пропущены)
len(rs.intersect((0,0,0),(1,0,0), 3.0, method="subdivision", m2_samples=2000))  # -> 2
```

(Ужесточение `region_tol` **не** помогает — область бугра исключается на грубом
уровне ещё до того, как бисекция туда добурится.)

### 7. Допуск объединения `auto` против точности

`_union` сливает корни ближе `1e-(precision/2)`. На практике это тоньше, чем
Штурм может разрешить при той же точности, поэтому, чтобы **сохранить**
по-настоящему близкую пару, вы повышаете точность — что поднимает и допуск
объединения, и разрешение Штурма вместе.

```python
expr = "(x - 1.0)*(x - 1.0000000000001)"              # корни в 1e-13 врозь
RaySurface(expr, 24).intersect((0,0,0),(1,0,0), t_max=2, method="auto")   # -> [1.0]      (слиты)
len(RaySurface(expr, 40).intersect((0,0,0),(1,0,0), t_max=2, method="auto"))  # -> 2  (precision=40)
```

### 8. Сингулярность производной на пути Ньютона (используйте Штурм)

```python
rs = RaySurface("(x-1)^5", precision=24)
rs.intersect((0,0,0),(1,0,0), t_max=3, method="sampling")
# -> ValueError ('nan'): d/dx от u^5 формируется как u^5·5·u'/u -> 0/0 в корне
rs.intersect((0,0,0),(1,0,0), t_max=3, method="sturm")    # -> [1]  (свобода от квадратов, точно)
```

### 9. Сэмплинг пропускает касательные / подшаговые корни

```python
rsA = RaySurface("x*x - 2*x + 1", precision=40)       # g(t)=(t-1)^2, касательный
rsA.intersect((0,0,0),(1,0,0), t_max=3, method="sampling")    # -> []   (нет смены знака)
rsA.intersect((0,0,0),(1,0,0), t_max=3, method="sturm")       # -> [1]
# два корня в 0.005 врозь внутри одного шага сэмпла также пропускаются сэмплингом.
```

### 10. Маршрутизация `auto` экзотических форм

`is_polynomial` синтаксичен. Он корректно отвергает `x^-2`, `x^0.5` и переменные
знаменатели (маршрутизируя их к общим бэкендам), но необычная запись может
проскользнуть — передавайте `method=` явно, если сомневаетесь.

```python
from formula._roots import is_polynomial
is_polynomial(RaySurface("x^-2 - 0.25", 24).surface)   # -> False (общий путь)
is_polynomial(RaySurface("1/(x-1) - 0.5", 24).surface) # -> False
is_polynomial(RaySurface("x^2 - 2", 24).surface)       # -> True  (натуральная степень)
```


## Выбор метода

| Поверхность | Рекомендуется |
|---|---|
| Полином / квадрика / конус / тор (умеренная степень) | `sturm` (или `auto`) |
| Гладкая аналитическая, мало корней, низкая осцилляция | `chebyshev` или `auto` |
| Осциллирующая / гофрированная / неизвестная | `subdivision` или `auto` |
| Комплекснозначная | `sturm` |
| Быстрая проверка, хорошо разделённые корни | `sampling` |
| Не знаю | `auto` |

Если сомневаетесь, `auto` — безопасное умолчание: он точен на алгебраических
поверхностях и согласует оба общих бэкенда в остальных случаях.
